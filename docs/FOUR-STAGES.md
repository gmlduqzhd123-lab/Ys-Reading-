# 책숲 4단계 개발 · 2026-10-30

## 확정 범위

글쓰기 활동은 우리 반 또는 교사들이 연결한 학년 모임 안에서 운영한다. 경제 교실은 책숲 내부의 학급별 화폐·상점·거래 기록이다. 전국대회, 실제 금전 결제, 외부 경제 서비스 연동은 이 범위에 포함하지 않는다.

| 단계 | 이번 구현 |
| --- | --- |
| 1 | 실제 Supabase 연결, 학급 초대·연결 신청·승인·활동 중지, 도서 검색과 수동 입력, 독서 기록 작성·수정·교사 확인, 기록·글·본인 초안의 Word/CSV/인쇄·PDF 저장, 교사용 Google Docs/Sheets 연결·생성 코드 |
| 2 | 서버 활동 기록, 캐릭터 이름·종류·레벨, 누적 경험치, 성취 배지와 교사 확정 월간 공동 수상, 한국 날짜 기준 학급별 하루 한 번 출석 |
| 3 | 학년 모임 생성·가입 요청·대표 승인, 학년 글쓰기 접수·검토·결과 확인, 학생의 공유 선택·교사 확인을 거친 광장 사본, 게시 취소·감상 반응 |
| 4 | 학급별 화폐 이름·보상 기준, 학생 지갑·교사 잔액 조회, 교사 지급·차감과 사유, 상품·재고·판매 중지, 구매 예약·지급·취소·자동 환불, 변경 불가능한 거래 기록 |

## 학생·교사 이용

주 진입점은 `/hub`이다. 기존 독서미션 배정·편집기·버전별 피드백은 `/app`에 유지한다. 로그인 없는 `/studio`는 브라우저 내 체험 공간이며 실제 학급으로 자동 전송하지 않는다.

학생 계정은 운영자용 `scripts/provision-user.ts`로 발급한다. 교사의 학생 연결 승인은 계정 발급이나 보호자 동의 확인을 대신하지 않는다. 실제 참여 동의가 확인되지 않은 학생은 활동·공유·보상·구매를 실행할 수 없다. 운영자는 실제 동의 근거를 확보한 절차로 참여 상태를 처리해야 한다. 개발용 가상 계정을 실제 학생으로 사용하지 않는다.

독서 기록은 같은 책에 여러 번 작성할 수 있다. 완독 기록을 교사가 확인할 때 보상하며, 확인한 기록은 학생이 덮어쓸 수 없다. 미션 완료 보상은 배정 미션마다 한 번, 고쳐쓰기 보상도 해당 미션마다 한 번이다. 글쓰기 참여 보상은 활동마다 한 번이다. 출석 보상은 한국 날짜·학급별 한 번이다. 재시도에는 같은 요청 ID를 사용하며, 같은 ID에 다른 내용이 오면 거부한다.

기본값은 완독 기록 20 XP/5 책잎, 미션 완료 30/10, 피드백 후 수정 완료 20/5, 글쓰기 참여 10/2, 출석 5/0이다. 교사는 다음 활동부터 적용할 기준을 바꿀 수 있다. 화폐 사용은 누적 경험치를 차감하지 않는다. 학급 활동이 중지되어도 동의가 유효한 학생의 획득 경험치·배지는 보존한다.

월간 독서왕은 교사가 확인한 완독 **기록 수**, 미션왕은 중복 없는 완료 활동 수, 출석왕은 학급별 참여일 수로 선정한다. 동률은 공동 수상하며 교사가 확정한 배지는 보존한다. 현재 월을 미리 확정하면 이후 활동이 순위를 바꾸더라도 이미 지급한 배지는 회수하지 않는다. 월말 운영을 권한다.

기록 목록은 페이지별 최대 100개, 참고 학급·프로필 목록은 최대 1,000개다. 경험치·지갑 합계는 화면 페이지와 별도로 전체 기록에서 계산한다. 내보내기는 선택한 순서로 최대 100개씩 처리한다. 페이지를 바꾸면 내보내기 선택은 초기화된다.

## 도서 검색

별도 키가 없으면 Open Library 검색을 사용한다. 국내 도서·판본의 검색 범위는 제공자 데이터에 따라 달라지므로 수동 입력을 함께 제공한다. `GOOGLE_BOOKS_API_KEY`가 설정되면 Google Books를 우선 사용하고 오류·빈 결과에 보조 검색을 시도한다. 검색 결과는 서버에서 캐시하며, 기록·학생 정보는 검색 제공자에 보내지 않는다. 제목·저자·ISBN 검색어만 보낸다.

## Google 연결 준비

Word·CSV 저장과 브라우저 인쇄·PDF 저장은 Google 설정 없이 동작한다. Google Docs·Sheets의 자동 생성에는 별도의 Google OAuth 앱 설정과 교사 승인이 필요하다.

1. 운영자의 Google Cloud 프로젝트에서 Drive API와 OAuth 동의 화면을 설정한다.
2. 웹 애플리케이션 OAuth 클라이언트를 만들고 리디렉션 URI를 실제 앱 주소의 `/api/google/callback`으로 등록한다.
3. 서버의 `GOOGLE_DRIVE_CLIENT_ID`, `GOOGLE_DRIVE_CLIENT_SECRET`, `GOOGLE_TOKEN_ENCRYPTION_KEY`, `NEXT_PUBLIC_APP_URL`을 설정한다. 암호화 키는 임의의 32바이트를 base64로 인코딩한다. 실제 값은 Git에 넣지 않는다.
4. `NEXT_PUBLIC_APP_URL`은 브라우저가 접속하는 주소·포트·프로토콜과 일치해야 한다. 배포 주소가 바뀌면 설정 후 다시 빌드한다.
5. 교사 계정의 ‘기록·글 내보내기’에서 Google 연결을 진행한다. 요청 범위는 `drive.file`이다.
6. 실제 교사 계정으로 승인·새 문서 생성·재시도·연결 해제를 확인한다. 이 실제 Google 계정 검증은 아직 수행하지 않았다.

연결 상태와 토큰은 서버 전용 키로 암호화한 HttpOnly 쿠키에 보관하고 계정 ID와 용도에 결합한다. 연결 해제는 이 브라우저의 토큰을 제거하며 이미 생성한 Google 파일은 유지한다. 내보내기는 사본 생성이고 자동 양방향 동기화는 제공하지 않는다. 새 Google 파일의 공유 상태는 사용자가 Drive에서 확인한다.

## 검증과 외부 연결

이번 검증은 실제 Supabase 프로젝트 `rbtqtkjnqtcnljvabisa`와 로컬 Next.js 프로덕션 서버를 사용했다. 가상 교사·학생의 인증, 학급 승인, 독서 기록, 미션 완료, 공유, 글쓰기 검토·발표, 학년 접수, 상점 구매, 출력 흐름을 확인했다. 실제 학생·실제 수업·학교 기기·물리적 인쇄 검증은 수행하지 않았다.

검증용 가상 계정·학급·활동·거래는 확인 후 식별자와 테스트 표식을 검사하는 마이그레이션으로 정리했다. 임시 로그인 경로는 앱에 포함되지 않으며 검증용 로컬 프로세스도 종료한다. 18개 원본 미션과 실제 운영에 필요한 빈 DB 구조를 유지한다.

공개 테이블은 RLS와 사용자 JWT를 사용한다. 스냅샷·보상·거래는 클라이언트 직접 쓰기를 허용하지 않고 인증·학급·동의를 검사하는 RPC로 처리한다. Supabase 보안 점검의 `SECURITY DEFINER` RPC 주의 항목은 이 의도된 구조를 가리킨다. 공개/익명 실행 권한 제거, 빈 search_path, 역할·학급 검사와 변조·중복·충돌 자동 검사로 검토했다. 이를 보안상 모든 위험이 제거되었다는 의미로 해석하지 않는다.

웹 호스팅은 아직 선택·배포하지 않았다. Vercel은 필수가 아니며 Node.js를 지원하는 호스팅을 사용하면 된다. 실제 운영 계정 발급, 개인정보·동의·보관·삭제 정책, Google OAuth 설정과 실제 승인, 학교 기기·수업 검토를 완료하기 전 실제 학생 운영 완료로 표시하지 않는다.
