# 학급 운영 흐름 검증 · 2026-10-31

대상은 `gmlduqzhd123-lab/Ys-Reading-`, Vercel `reading`, Supabase `rbtqtkjnqtcnljvabisa`이다. 실제 운영자와 구분되는 가상 교사·운영자·학생, 가상 학급 두 개로 검사했다. 가상 교사 권한은 테스트 준비 단계에서 지정했으며 실제 교사 신원 심사를 검증한 것으로 보지 않는다. 학생 계정은 배포된 `account-operations` 함수가 Supabase Auth에 발급했다. 동의 근거는 `SYNTHETIC` 표식이며 실제 보호자 동의가 아니다.

## 발견한 문제와 개선

- 한국 시각 00:00~08:59에 입력한 당일 동의 확인일이 UTC 서버에서 미래로 판정됐다. `operations_command`의 함수 실행 시간대를 `Asia/Seoul`로 고정했다. 기존 권한 검사·빈 `search_path`·호출 권한은 유지하며 호출자의 시간대는 반환 시 복원된다. 실제 한국 날짜로 동의 요청·승인을 재검증했다.
- 학급 생성 화면에 계정 발급을 운영자가 한다는 오래된 안내와 내부 UUID가 남아 있었다. 담당 교사의 발급 절차, 학생 자동 학급 연결, 동의 승인, 미션 배정 순서를 안내하고 학급별 발급 링크를 추가했다. 계정 관리 진입 시 담당 학급 목록 안에서만 선택값을 반영한다.
- 학생 화면이 이미 연결된 학생에게도 초대 코드 입력을 우선 안내했다. 연결된 학급과 미션 이동을 표시하고, 별도의 학급 신청은 접을 수 있는 안내로 옮겼다.
- 화폐 지급 대상에 다른 담당 학급의 학생까지 함께 나왔다. 선택한 학급의 활동 중인 학생만 표시하고 학급 변경 시 이전 지급 입력을 초기화한다. 학생이 없는 학급에서도 다른 학급으로 전환할 수 있다. 서버·DB의 소속 검사는 계속 적용된다.
- 상점에서 품절·판매 중지·잔액 부족을 구매 전에 표시한다. 실제 재고와 잔액의 최종 판정은 서버가 수행한다.

## 정리와 회귀 검사

가상 학생은 제품의 삭제 요청 → 운영자 승인 → Edge 실행 절차로 삭제했고, 삭제한 계정의 재로그인 거부를 확인했다. 남은 가상 교사·학급은 이번 실행의 정확한 UUID, 테스트 이메일·표식·소유권, 학습 데이터가 먼저 비워졌는지를 검사한 트랜잭션으로 정리했다. 원격 최종 집계는 사용자 1명·운영자 1명, 학급·독서 기록·제출 글·경제 원장 0건이다. 실제 운영자는 유지했다. 테스트 비밀번호·세션·초기 계정표는 저장소에 포함하지 않는다.

`npm run check`: 타입 검사, 18개 파일의 232개 테스트, Production 빌드 통과. 한국 날짜의 동의 요청/미래 날짜 거부/호출자 시간대 복원, 반별 지급 대상·정지·활동 중지 계정 제외 회귀 검사를 추가했다. 보안 advisor도 다시 조회했다. 등록된 인증 전용 함수의 SECURITY DEFINER 경고와 기존 Auth 비밀번호 유출 방지 설정 경고는 별도 운영 설정이며 이번 날짜 수정으로 호출 권한을 확대하지 않았다.
