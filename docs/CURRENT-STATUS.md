# 책숲 현재 개발 상태 · 0.7.0

최신 7가지 개선과 사용 범위는 [수업 기록 복구와 전체 이력 관리](CLASSROOM-OPERATIONS-0.7.md)를 기준으로 확인합니다. 아래는 유지되는 0.6.0 기능 이력입니다.

## 0.6.0 기능 이력

최신 수업 기능 10가지는 [매일 독서와 수업 공방](CLASSROOM-WORKSHOP-0.6.md)을 기준으로 확인합니다. 기존 독서·글쓰기·보상·경제·Google/파일 내보내기를 유지하고 간편 기록·실학급 시연·활동지 배부·활동 카드·근거 조회·도감·독서 리듬·보호자 공유·보유 도서·교사 퀴즈를 연결했습니다. 선택형 AI 실제 생성은 별도 설정이 필요하며 아래는 이전 릴리스 이력입니다.

최신 보완 범위와 남은 사용자 준비 사항은 [0.5.0 운영 보완](OPERATIONS-0.5.md)을 기준으로 확인합니다. 백업 연결 경로·사본 최신성·교사 초안 오류 복구·내보내기 사용량·복구 사전 점검·현황판 조회·협업 입력을 보완했습니다. 실제 통과 결과는 해당 커밋의 CI와 릴리스 검증을 확인합니다. 아래 내용은 이전 릴리스의 기능 이력입니다.

현재 5가지 개발 범위는 [0.4.0 운영 보완](OPERATIONS-0.4.md)이다. 내보내기 한도·중복 방지, 사본 실패 보고, 교사 비공개 초안, 서버 ZIP, 과거 기록 집계를 보완했다. 실제 검사·배포 결과는 해당 커밋의 GitHub Actions와 릴리스 보고를 기준으로 확인한다. 아래 0.3.0 표는 기존 기능과 운영 준비 범위의 이력이다.

이번 8가지 보완과 남은 운영 설정의 기준은 [0.3.0 운영 보완](OPERATIONS-0.3.md)입니다. 과거 날짜별 백로그는 당시 이력이며, 최신 통과 결과는 해당 커밋의 GitHub Actions와 릴리스 보고를 확인합니다. 아래는 유지되는 0.2.0 기반 기능입니다.

| 이번 항목 | 구현 | 실제 운영·설정의 범위 |
| --- | --- | --- |
| 1. 반복 서버 오류 진단 | DB·Auth·연결 대기·호스팅·시간 초과·요청 제한 구분, 문의 번호·배포 SHA·응답 시간을 14일 보관, 운영자 이력 | 과거 만료된 런타임 로그의 원인을 확정한 것은 아님. 이후 점검 결과부터 최소 진단 수집 |
| 2. 독서 임시 저장·복구 | 개인 서버 초안, 중복 요청·revision 충돌 방지, 선택형 탭 보관, 복원 선택, 작성 도움 메모 포함 | 정식 독서 기록·완독 확인·보상과 분리. 서버 초안 7일 유효, 만료분 매시간 삭제. 탭 사본은 24시간 유효·로그아웃 시 제거 |
| 3. PC 무응답·사본 검증 | PC 보고 2시간 신선도와 백업 48시간 신선도 분리, 사본 암호문 읽기·격리 복원·최신 digest 대조, 자동 갱신 | 사용자가 지정한 바탕화면 복구 폴더는 **같은 PC 사본**. USB·네트워크·다른 PC 보관으로 기록하지 않음 |

| 6. 학교 현장 검증 | 이번 요청에서 제외 | 실물 기기·학교망·학교 Google 관리자 정책은 미검증 |
| 7. 국내 도서 검색 | 알라딘·카카오 우선 연결, 장애 시 기존 제공자 전환, ISBN 체크·판본 구분·중복 제거, 비공개 키 입력 도구 | 사용자 선택으로 키 발급·국내 제공자의 실제 연결은 대기. 다른 검색과 직접 입력은 유지 |
| 8. 버전·현황 정리 | 상태 화면·헬스 API에 빌드 커밋·시각·수정본 구분, DB·작업자 호환 검사, 현재 문서 분리 | 배포 커밋과 운영 도메인 연결은 매 릴리스에서 따로 확인 |

기존 학급 생성·학생 발급·동의·독서·글쓰기·검토·Google/파일 내보내기·광장·신고·성장·배지·학급 경제·학기 진급·공동교사·개인정보 보관 기능을 유지합니다. 글쓰기 행사는 학급·연결 학년 규모이며 화폐는 학급 활동용입니다.

## 운영 도구

- 즉시 새 예약 백업: `node scripts/operator-request-backup.mjs`
- 같은 암호화 키로 준비한 복구 묶음을 사본 대상으로 지정: `node scripts/operator-configure-copy.mjs "전체 복구 묶음 폴더"`. 암호화된 설정에 보관하고 예약 작업에서 갱신·검증합니다. 바탕화면 폴더 안의 기존 `Bookforest-Recovery-…` 묶음을 사용합니다.
- 사본 즉시 검사: `node scripts/operator-check-copy.mjs`. 실패를 새 백업 성공으로 바꾸지 않으며, 보고가 안 되면 로컬 `copy-status.json`에 남깁니다.
- 설정 암호화 내보내기: `node scripts/operator-recovery-settings.mjs export`. 현재 운영자 PC의 승인된 `.env.local` 항목만 보관하며 서비스 역할 키·무관한 환경 변수는 제외합니다. Supabase 대시보드 설정 전체 백업과 다릅니다.
- 별도 대상 준비: `operator-recovery-settings.mjs inspect/prepare`에 복구 폴더·암호·대상 설정을 비공개 표준 입력으로 전달합니다. 운영 프로젝트·도메인을 대상에 쓸 수 없고 기존 `.env.local`을 덮어쓰지 않습니다. Google 콜백·제공자 설정·계정 작업자·최신 개인정보 대조는 별도로 확인합니다.
- 국내 도서 키: `powershell -NoProfile -STA -File scripts/Import-Book-Key.ps1`. 키는 채팅·명령행 인자·로그에 넣지 않고 실제 제공자 응답 확인 후 로컬에 보관합니다. 공개 연결 전에는 같은 키를 Vercel Production의 비공개 환경 변수에 등록하고 재배포합니다.

API 한도는 도서 검색 사용자별 30회/분, 심층 연결 점검의 일자별 익명화 접속 단위 120회/분, 기능별 전체 600회/분입니다. 원문 IP를 DB에 보관하지 않으며 후속 요청에서 지난 시간 구간의 버킷을 정리합니다. 서명 키는 서버와 private DB에만 보관합니다. 설정·서명 검증 경로가 실패하면 무제한으로 우회하지 않고 재시도를 안내합니다.

PC 보고만 끊기고 기존 백업이 여전히 유효한 경우에는 GitHub 경고 이슈로 알리되 백업 실패로 CI를 실패시키지 않습니다. 실제 백업 실패·인증 실패·48시간 초과는 계속 실패로 판정합니다.
