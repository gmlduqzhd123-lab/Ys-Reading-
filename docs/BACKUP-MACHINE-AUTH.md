# 자동 백업 전용 인증 · 0.8.1

자동 작업은 `scripts/lib/backup-machine.mjs`의 전용 경로를 사용한다. 개인 MCP 로그인, Codex 실행 파일, 계정 전체 Management API 토큰을 호출하지 않는다. 수동 운영·초기 등록 도구의 MCP 연결과 구분한다.

- 최초 등록: 기존 운영 권한으로 프로젝트 `rbtqtkjnqtcnljvabisa`와 설치된 RPC를 확인한 뒤 `node scripts/operator-machine-auth.mjs setup`을 실행한다. 256비트 무작위 키는 이 Windows 계정의 DPAPI로 보호한 보관함에 암호화한다. 채팅·GitHub·Vercel 환경 변수에 복사하지 않는다. DB에는 키 해시만 저장한다.
- 자동 작업 권한: 전체 논리 백업 읽기, 현재 개인정보 삭제·동의 체크포인트 읽기, 제한된 백업 영수증, 서버 암호화 파일 다운로드 요청·복원 검증 영수증, 사본 검증 영수증만 허용한다. 임의 SQL, 학생 계정 수정, 일반 테이블 API 접근, 프로젝트 변경은 허용하지 않는다. 상태 보고용 HMAC 키는 이 권한을 받지 않는다.
- 키 교체: 사용 시 30일이 지난 키를 자동 교체한다. 다음 키를 암호화 보관한 뒤 서버를 바꾸며, 응답 유실·중단 후 다음 실행에서 교체를 마무리한다. 이전 키는 최대 7일 동안 겹쳐 사용할 수 있다. 취소된 인증은 두 키 모두 즉시 거부한다. OAuth 로그인 만료로 중단되지 않으며 전용 인증 실패를 MCP 로그인으로 조용히 우회하지 않는다.
- 상태 확인: `node scripts/operator-machine-auth.mjs status`. 수동 교체: `node scripts/operator-machine-auth.mjs rotate`. 키 내용은 출력하지 않는다. 관리자 취소는 해당 프로젝트의 `private.backup_machine_credentials`에서 대상 ID만 비활성화한다. 새 PC·실제 운영 복구 시에는 운영자가 별도 등록하고 이전 PC의 인증을 검토한다. 백업에 있는 해시로 인증 키를 복원할 수 없다.
- PC 예약: 기존 기본 백업과 감시 작업을 사용한다. PC 전원·Windows 로그인·네트워크가 필요하다. 새 백업·복원 검증이 끝나야 인증 장애를 복구로 처리한다. 재시도 대기 중인 실패를 정상 종료로 표시하지 않는다.

## 반복 알림 정책

서비스 연결 검사 실패와 알림 전송·확인 실패는 GitHub 실행 실패로 유지한다. 알려진 백업 장애는 실제 운영 이슈가 등록·확인된 경우에만 점검 실행 자체의 오류와 구분한다. 백업 상태는 계속 `healthy:false`이며 운영 보고서·공개 상태 화면에 표시한다. 알림 영수증 누락, 오래된 결과, 상태 불일치, 조회 실패는 실행 실패다. 이슈는 같은 원인에 대해 한 개를 유지하고 원인 변경·실제 복구 시에 갱신한다.

알림 감시는 현재 실행에서 이미 완료한 알림 단계를 확인할 수 있으므로, 직전 예약 실행이 오래됐다는 이유만으로 현재의 정상 전달을 계속 지연으로 판정하지 않는다. 예약 자체가 늦어지는 경우와 전송 실패는 구분한다. GitHub의 예약 실행 시각을 보장하지 않는다.

서버 암호화 파일 생성과 PC의 실제 복원 검증, 같은 PC 폴더와 외부 저장 장치, 격리 복구 검사와 운영 서버 전환은 계속 구분한다. 이 변경은 다른 실물 PC·별도 제공자로 운영 전환을 완료한 기록이 아니다.
