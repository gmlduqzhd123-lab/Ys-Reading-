# 학급 운영 흐름 완성 · 2026-11-04

이번 개발은 앞선 [운영 확대](OPERATIONS-2026-11-04.md)에 이어 다음 여덟 항목을 보완합니다. 최종 CI·공개 배포 결과는 해당 커밋과 릴리스 채팅을 확인합니다.

1. **공동교사 검색·현황판**: 읽기 권한을 받은 학급만 기존 검색과 현황판에서 확인합니다. 읽음 시각은 교사별로 따로 기록합니다. 학생 개인 초안, 다른 학급, 철회된 동의, 회수·만료된 권한을 허용하지 않습니다.
2. **백업 외부 알림**: GitHub가 공개된 최소 백업 신호를 점검합니다. 최근 검증이 48시간 넘게 없거나 실행 실패·인증 오류·30분 넘는 실행 정체를 알립니다. 서비스 장애와 다른 사건으로 관리하고 새 백업 성공 후 닫습니다. 학생 수·내용·파일명·경로·키는 공개하지 않습니다. PC 전원·로그인·Codex 인증 조건은 유지합니다.
3. **Google 작업 상태와 권한 회수**: 같은 사용자의 같은 요청은 DB에서 하나의 작업만 실행합니다. 자료가 다른 동일 요청은 거부합니다. 업로드 응답이 불확실하면 Drive에서 같은 요청의 파일을 확인하고, 없다고 바로 두 번째 파일을 만들지 않습니다. 다른 요청 번호로 무작정 재시도하지 말고 Drive의 ‘책숲 기록’ 폴더를 먼저 확인합니다. ‘이 브라우저 연결 해제’는 쿠키만 지우고, ‘Google 접근 권한 회수’는 Google의 확인 후 연결을 지웁니다. 기존 문서는 두 경우 모두 유지합니다.
4. **학급 규모와 보고서 성능**: 보고서 미리보기는 30명의 요약을 한 번의 RPC로 받습니다. 본문을 미리보기 목록으로 보내지 않으며 준비·저장 중 상태와 다음 30명을 표시합니다. CI는 3개 학급·90명·과거 독서 2,700건을 포함합니다. 합성 CI의 속도를 실제 운영 서버·학교망 성능으로 해석하지 않습니다.
5. **모바일·접근성**: WebKit 휴대전화 크기에서 별도 학생으로 로그인·한글 글 저장·새로고침·연결 끊김 후 저장·내보내기 화면을 검사합니다. axe와 키보드 초점을 확인합니다. 한글 IME 조합, 실물 iPad·학교 PC·학교망과 학교 Google 관리 정책은 현장 검사가 필요합니다. `/device-check`에서 그 기기로 실행한 항목만 확인합니다.
6. **최신 개인정보 상태와 복구**: 백업과 별도로 암호화된 `privacy-current.bfguard`를 보관합니다. 계정 삭제, 동의·활성 상태, 학급 참여 회수, 삭제 결정 시각을 이름·본문 없이 담습니다. 24시간을 넘겼거나 다른 프로젝트의 확인 파일은 거부합니다. 복원 시 최신 확인 파일과 대조해 과거 데이터와 충돌하면 접근을 보류합니다. 복원 검증 성공이 서비스 공개 승인을 뜻하지 않습니다. 외부 Drive 사본은 `/account/records`에서 별도 정리 확인을 합니다.
7. **역할별 메뉴·이어서 준비**: 허용된 학급과 읽기·검토·담임 역할에 맞는 메뉴를 표시합니다. 학급 준비의 단계·학급 ID만 해당 계정의 탭 저장소에 24시간 보관합니다. 초기 비밀번호·명단·동의 자료를 저장하지 않습니다. 다시 열면 계정 안내표와 발급 재개를 확인하도록 안전한 단계로 돌아갑니다.
8. **광장 확인 요청**: 게시된 작품의 개인정보·상처 주는 내용·기타 도움을 담당 교사에게 요청합니다. 신고자와 해당 담임만 요청 내용을 읽으며, 다른 학생·다른 학급 교사·공동교사에게 공개하지 않습니다. 담임은 게시 유지 또는 게시 중단을 기록합니다. 게시 중단은 불변 작품 원문을 고치지 않으며 중복 요청과 이전 revision 처리를 차단합니다.

동시 사용 검사에서 연결 대기 시간 초과(`PGRST003`)를 확인해, SQL이 실행되기 전의 이 오류에만 짧은 무작위 간격으로 최대 3회 재시도합니다. 권한·입력 오류, 다른 서버 오류와 결과가 불확실한 네트워크 오류는 자동 재실행하지 않습니다. 독서 기록 접근 정책은 해당 교사가 읽을 수 있는 학급을 SQL 문장마다 한 번 확인하며, 학생의 본인 기록과 공동교사의 동의·참여·권한 회수 조건은 유지합니다. CI 결과에는 실제 연결 대기 재시도 수도 별도로 표시합니다.

## 복구 시 개인정보 확인

- 다른 PC에 `backup.bfbak`, `recovery.bfkey`, `privacy-current.bfguard`, `receipt.json`을 함께 옮기고 암호는 따로 보관합니다. 이 PC의 폴더 생성만으로 외부 보관 완료를 기록하지 않습니다.
- 원본 프로젝트에 접근할 수 있으면 최신 백업을 실행해 개인정보 확인 파일을 갱신합니다. 접근할 수 없고 확인 파일도 오래됐다면 임의로 최신이라고 간주하지 않고 복구된 서비스의 공개를 보류합니다.
- 복원 대상은 운영과 다른 격리 환경이어야 합니다. 기존 백업에 복구 상태 테이블이 없으면 먼저 검토된 최신 마이그레이션을 적용합니다. 운영 DB를 과거 파일로 덮어쓰지 않습니다.
- `private.recovery_state.held=true`는 서비스 접근 보류입니다. `private.recovery_denials`의 원문 없는 식별자·범위를 확인하고, 승인된 삭제·동의 상태와 외부 사본 정리를 대조합니다. 실제 삭제는 원래 승인 범위와 기간을 따릅니다. 새 자료를 보존해야 하므로 임의 전체 삭제를 하지 않습니다.
- 프로젝트 소유자는 접근 보류를 해제하기 전에 별도 환경에서 계정·학급 권한·비공개 기록·삭제·Google 재연결을 확인하고 운영 주체의 확인을 남깁니다. 자동 도구는 이 확인을 대신하지 않습니다.
