# 실제 계정용 참여 기능 10가지

구현·검증일: 2026-10-31. 사용자가 승인한 개발 순서는 1 → 2 → 6 → 3 → 4 → 5 → 7 → 8 → 9 → 10이다. 학급·연결된 학년 안에서 이용하며, 경제 교실은 책숲 내부 학급 화폐다.

| 번호 | 기능·진입 | 실제 동작 |
| --- | --- | --- |
| 1 | 교사 `/start` 학급 준비 | 학급 생성 → 학생 발급·실패 행 재시도 → 첫 선택형 미션 → QR·안내문·CSV. 초기 암호는 준비 화면 메모리에만 두고 CSV 저장 전 이동을 막는다. 동의 대기 계정을 자동 활성화하지 않는다. |
| 2 | `/hub?tab=today` 오늘 | 학생은 독서·글쓰기·캐릭터 세 갈래와 수정 요청·작성 중·새 미션 순으로 이어 한다. 교사는 준비·확인함·수업 꾸러미로 이동한다. 이전 `/app?view=missions`도 유지한다. |
| 6 | 교사 `review` 확인함 | 최신 제출본과 확인 전 완독 기록을 모은다. 본문을 연 뒤에만 선택할 수 있고, 최대 20건을 원자적으로 완료·수정 요청·독서 확인한다. 문구 저장·불러오기와 학급 필터를 지원한다. |
| 3 | `bookshelf` 질문 도움 | 한 문장·세 질문·자유 기록을 고르고 장면·감정·생각을 자기 기록에 명시적으로 덧붙인다. 편집 중 내용을 모드 변경만으로 지우지 않는다. |
| 4 | 배정된 글쓰기 | 편지·새 결말·질문 중 학생이 고른 표현 방식으로 작성한다. 선택 전 저장을 DB에서도 막으며 내용 작성 후 선택을 바꿀 수 없다. 배정 당시 선택지·기준을 고정한다. |
| 5 | `growth` 공동 숲 | 기존 캐릭터·XP와 연결하고, 목표 생성 후 교사가 확인한 활동으로 반의 공동 목표가 자란다. 실제 기여 학생만 배지를 한 번 받는다. 공개 개인 순위나 접속 중단 페널티는 없다. |
| 7 | `exhibitions` 전시 | 학생의 광장 게시 동의에 더해 해당 전시·제출 버전에 별도 동의를 받는다. 교사가 승인한 작품만 반·연결 학년에서 보고 Word·Google Docs·Sheets 공동 작품집을 만든다. 참여 취소를 지원한다. 필명 포함은 선택이며 기본 제외다. |
| 8 | `economy` 역할 경제 | 역할 신청 → 교사 배정 → 학생 완료 보고 → 교사 확인·보수 지급. 기존 거래 원장에 한 번만 지급한다. 저축 목표는 잔액 진행도이며 별도 예금·돈 이동이 아니다. 학생 상품 제안은 교사 가격·수량 확인 후 상점에 등록한다. |
| 9 | 교사 `packs` 수업 꾸러미 | 선택지·기준·피드백 문구·공동 목표를 함께 저장하고 공유·복제·수정·배정한다. 다른 교사는 공유 자료만 복제한다. 원본 수정은 이미 배정한 활동을 바꾸지 않는다. |
| 10 | 공통 보기·복구 | 큰 글씨·뚜렷한 대비·움직임 줄이기를 기기에 저장한다. 학생 본문·인증정보는 이 설정에 넣지 않는다. 기존 초안 자동저장·충돌 감지·저장 상태와 새 명시적 새로고침·재시도를 사용한다. |

## 권한과 데이터

- 마이그레이션 `20261031045914_classroom_participation.sql`을 지정 Supabase 프로젝트에 적용했다. 로컬과 원격 이력은 13개로 일치한다.
- 새 공개 테이블은 RLS와 명시적 SELECT 정책을 적용하고 anon·authenticated의 직접 쓰기를 회수한다. 명령 RPC는 실제 세션·역할·담당 학급·참여 동의를 다시 검사한다.
- 같은 명령의 재시도는 요청 UUID·본문 지문과 행 잠금으로 중복 배정·급여·상점 등록·배지를 막는다. 재시도 테이블에 학생 글을 복사해 보관하지 않는다.
- 기존 삭제 승인·미활동 판정·미리보기·실행에 새 기록을 포함한다. 학급 기록만 삭제하면 다른 반의 저축 목표를 지우지 않는다. 원장과 보고서의 상태 전이를 검사한다.
- 광장 공개 범위와 전시 공개 범위를 함께 검사한다. 넓은 전시를 선택했다고 좁은 광장 게시물이 넓어지지 않는다. 작품집은 생성 시점의 사본이므로 후속 게시 취소가 이미 만든 사본을 자동 삭제하지 않는다.
- 화면 조회는 최근 전시·꾸러미·목표 등 100개, 전시 작품 500편, 일부 개인·역할 기록 1,000개로 제한하며 화면에서 알린다. 대규모 장기 운영은 페이지 분할·부하 검증이 추가로 필요하다.

## 실행한 검사

- 타입 검사, 24개 파일의 자동 검사 **290개**, 프로덕션 빌드 통과. PGlite 실제 PostgreSQL 검사로 역할·RLS·직접 쓰기 차단·동의 철회·교차 학급·상태·재시도·삭제 범위를 확인했다.
- 실제 Supabase Auth·Edge·DB에 명확히 표시한 가상 계정을 만들고 계정 발급·첫 암호 변경·동의 제한·운영자 확인·읽기·글쓰기·수정·광장·보상·구매·환불 흐름을 검증했다. 실제 보호자 동의 확인을 대신하지 않는다.
- 실제 브라우저에서 학급 생성·학생 발급·CSV 저장·QR 생성·첫 배정, 선택 후 초안 저장·v1 제출·교사 수정 요청·v2 제출·교사 완료, 세 질문 독서 기록·두 건 일괄 확인, 공동 숲 배지, 역할·보고·급여·저축·상품 승인, 꾸러미 복제·수정·배정을 확인했다.
- 전시는 학생의 별도 동의와 교사 승인을 거쳤다. 앱에서 Word 작품집을 내려받아 ZIP/XML의 제목·최신 수정본·운영자 이메일 제외를 확인했다.
- 실제 공개 주소의 개인 독서·글쓰기 Google Docs·Sheets 생성은 앞선 Drive 오류 수정에서 확인했다. 이번 공동 작품집의 공개 주소 검증과 최종 배포·정리 결과는 `VERIFICATION.md`의 최신 항목에 기록한다.
- 보안 Advisor에는 의도된 비공개 RLS 무정책 INFO 3건, 인가된 SECURITY DEFINER RPC WARN 17건과 기존 유출 암호 보호 미활성 WARN이 남는다. 이를 무경고 상태로 보고하지 않는다. 함수의 내부 인가는 별도 검사로 확인했으며 이번 작업에서 관련 없는 Auth 설정을 변경하지 않았다.

## 운영 전 확인할 범위

Google OAuth 앱은 테스트 모드다. 다른 학교 계정의 정책·테스트 사용자/공개 요건을 확인해야 한다. 실제 학생·보호자의 동의, 학교 보관 정책, 실물 학교 기기·QR 카메라 스캔·대규모 동시 접속·실제 수업은 검증하지 않았다. 가상 검증 자료를 실제 학생 성과로 표시하지 않는다.
