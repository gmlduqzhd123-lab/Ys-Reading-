# 책숲 0.5.0 · 복구 안정화와 작성·내보내기 보완

1. 예약 백업의 연결 방식을 선택할 수 있다. 기존 Codex MCP는 유지하며, 운영자가 직접 발급한 **책숲 프로젝트 한정** PAT를 비공개 입력창에서 설정하면 Management API로 실행한다. Project Settings 읽기, Database 읽기/쓰기만 필요하다. `powershell -NoProfile -STA -File scripts/Configure-Backup-Access.ps1`로 입력하며 토큰을 채팅·명령행·로그에 넣지 않는다. 최대 90일 만료 정보를 함께 암호화 보관하고 만료·401·403을 구분한다. 설정된 토큰이 실패하면 다른 계정으로 자동 전환하지 않는다. 토큰은 사용자 발급 전까지 비활성이다. Management API의 query는 현재 Beta이므로 장애 시 원인을 남기고 제한된 간격으로 재시도한다. PC 전원·운영자 Windows 로그인 조건은 유지한다.
2. 사본 보고 v2는 원본 생성 시각을 서명된 보고에 포함한다. 복사 검사 시각이 오늘이어도 원본이 48시간을 넘었거나 최신 백업 digest와 다르면 정상으로 처리하지 않는다. 기존 v1 보고는 수신하되 생성 시각 미확인으로 재검사를 요청한다. 같은 PC 사본은 외부 사본으로 표시하지 않는다. 원본 생성·사본 복원 검사·최신 백업 일치를 각각 표시한다.
3. 교사 초안은 일시 연결 오류만 최대 세 번 지연 재시도하며 요청 UUID를 유지한다. 권한 오류와 revision 충돌은 자동 덮어쓰지 않는다. 충돌 시 다른 화면의 초안과 현재 입력을 비교하고 사용자가 선택한 내용을 새 revision으로 저장한다. 파일은 교사·학급·학생·기간을 포함한 전용 형식이며, 다른 맥락의 파일을 불러오지 않는다. 기존 0.4의 일반 JSON 파일은 자동 적용하지 않는다. 로그아웃 시 메모리를 비우며 파일 저장은 사용자가 선택한다. 최종 전송·학생 공개·읽음 확인은 별도이다.
4. 내보내기 사용량에는 보관 수·한국 날짜 생성 수·원문·개인 생성 파일·서비스 공용 파일 용량을 표시한다. ZIP 다운로드 전 HEAD로 현재 권한과 상태를 확인하고 GET에서 요청 한도를 확정한다. 401/403/409/429/503을 구분하며 429에는 Retry-After를 제공한다. 파일은 계속 서버에서 순차 전송한다. 다운로드 요청을 기기 저장 완료라고 표시하지 않는다. 권한 변경으로 전송이 중단되면 재확인 후 다시 받는다. 실패·중단한 파생 파일은 24시간 뒤 정리하며 정본과 내보내기 고정 사본은 7일 보관 규칙을 유지한다. 매분 처리 순서를 갱신해 오래 막힌 작업이 앞자리를 독점하지 않게 한다.
5. `node scripts/operator-recovery-preflight.mjs <준비한 대상 .env의 절대 경로>`는 별도 프로젝트·HTTPS 앱 주소·공개 키를 검증하고 앱/DB/계정 작업자/ZIP 엔드포인트를 검사한다. 환경 변수 내용·비밀키를 출력하지 않는다. Google·Supabase 콜백과 남은 수동 로그인·내보내기 확인 목록을 출력한다. 이 검사는 실제 도메인 전환이나 학교 기기 승인과 다르며 `operationalCutoverVerified:false`를 유지한다. 실제 복구 대상 생성·외부 저장 장치 지정·콜백 등록은 별도 승인과 준비가 필요하다. 백업 복원 검사는 ZIP 보조 역할의 NOLOGIN/NOBYPASSRLS 및 비활성 작업 설정도 검사한다.
6. 교사 현황판의 최근 활동은 보안 뷰를 유지한 채 학생별·기록 종류별 최신 한 건을 인덱스로 조회한다. 대량 이력 전체에 RLS를 반복 적용하는 비용을 줄인다. 격리 PostgreSQL CI에서 3만 건의 변경 전/후 결과 일치와 측정 시간을 비교한다. 실제 학교 장비의 응답 속도를 보장하지 않는다.
7. 권한으로 볼 수 있는 학교는 이름으로 선택한다. 목록에 없는 학교는 관리자에게 받은 연결 코드를 직접 입력해 승인 요청할 수 있다. 초대 대상·역할·권한을 최종 확인한 후 코드를 만들고, 복사 버튼으로 지정 교사에게 전달한다. 이메일을 자동 발송하지 않는다. 대체 운영자 본인 수락·MFA 및 국내 도서 API 키 발급은 계속 사용자 준비 사항이다.

DB 변경은 `recovery_operations_v05`와 과거 권한 오류가 새 백업 이후 되살아나지 않도록 하는 `backup_permission_freshness` 마이그레이션으로 관리한다. `recoveryOperations` 릴리스 계약을 검사하며 기존 계정 작업자의 protocol 2를 유지한다. 운영 정본에 합성 학생·학급을 만들지 않는다.
