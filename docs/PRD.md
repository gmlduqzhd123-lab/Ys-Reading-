## 1. 제품 목표와 최초 이용자

책을 읽고, 질문을 만들고, 자기 생각을 쓰며, 피드백을 받아 고치는 경험을 연결한다. 독서미션에서 만든 기록은 선택 참가 방식의 글쓰기 대회와 개인 작품 기록으로 이어진다. 접속 시간·글자 수·독서 권수를 교육 성취와 동일시하지 않는다.

최초 대상은 초등 3~6학년 학급·독서동아리다. 담당 교사가 학급과 미션을 운영하며 학생은 자기 글과 배정받은 활동을 확인한다. 저학년, 학부모 대시보드, 도서관·지역기관 연합, 전국대회는 검증 후 확장한다.

초기 콘텐츠는 용기·공감·공정 × 3~4학년·5~6학년 × 질문·글쓰기·수정의 18개 자체제작 활동이다. 학생은 접근 가능한 책을 고른다. 특정 상업 도서의 본문·표지 제공이나 이용 허락이 확보되었다고 가정하지 않는다. 활동 예상 시간은 독서 시간이 아닌 읽은 뒤의 활동 시간이다.

## 2. 핵심 여정

1. 교사가 권한을 확인받고 학급을 만든다.
2. 필요한 동의와 참여 조건을 확인한 학생이 담당 학급에 참여한다.
3. 교사가 학년군·주제에 맞는 미션을 배정한다.
4. 학생은 읽은 책을 바탕으로 초안을 저장하고 제출한다.
5. 교사는 해당 제출 버전에 피드백을 남기고 수정 요청 또는 완료 처리한다.
6. 수정 요청을 받은 학생은 새 초안을 작성하고 새 버전을 제출한다.
7. 완료 기록과 근거 있는 배지를 확인한다. 출품 자격이 있는 학생은 원할 때만 학급 대회에 참가한다.
8. 대회 마감 시점의 별도 심사본을 기준으로 심사한다. 학생의 이후 학습용 수정은 심사본에 영향을 주지 않는다.

## 3. MVP 범위

### 포함

- 한국어 반응형 화면, 읽을 수 있는 글자 크기, 키보드로 조작 가능한 입력·버튼.
- 공개 미션 목록, 주제·학년군 필터, 검색, 활동 상세와 단계별 안내.
- 실제 Supabase 인증, 서버에서 확인하는 사용자·학급 권한, 동의 상태에 따른 접근 제한.
- 학급 생성·참여, 미션 배정, 개인 초안 저장, 제출 버전 보존.
- 교사 피드백, 수정 요청, 수정본 제출, 완료 처리.
- 자기 활동 기록과 규칙 기반 배지. 대회 참가 여부와 분리.
- 학급 단위 대회, 명시적 선택 참가, 마감 판정, 심사본 고정, 기준표 심사.
- 입력 검증, 중복 요청 방지, 초안 충돌 감지, 오류 안내, 핵심 권한·상태 테스트.

### 후속 단계

- AI 독서·글쓰기 코치, AI 자동 채점, 맞춤 추천 엔진.
- 학생 간 자유 채팅, 공개 커뮤니티, 실시간 공동 집필, 동료 피드백.
- 복잡한 아바타 경제, 아이템 상점, 공개 개인 순위표.
- 전국대회, 외부 심사위원 다중 배정, 이의 제기 전용 화면, 기관별 계약·결제.
- 교사 공개 콘텐츠 장터, 도서관 도서·대출 API 연동, 지역 행사, 자동 작품집 출판.
- 음성·영상·그림 제출 및 저학년 보호자 동반 흐름.

## 4. 역할과 권한

| 역할 | 허용 범위 | 제한 |
| --- | --- | --- |
| 방문자 | 공개 미션 콘텐츠 읽기 | 학생 작품·학급·개인 기록 접근 불가 |
| 학생 | 참여 학급의 배정 미션, 자기 초안·제출본·피드백·대회 참가 기록 | 다른 학생 글 열람·교사 기능·자기 역할 변경 불가 |
| 담당 교사 | 자신이 담당하는 학급의 배정·검토·대회 운영 | 다른 학급 자료 접근, 동의 근거 없이 학생 참여 처리 불가 |
| 운영 담당자 | 확인된 교사 권한·동의·운영 예외 처리 | 운영 권한 자체에 검증·기록 필요; 브라우저에 특권키 배포 금지 |

권한은 화면 숨김에만 의존하지 않는다. 서버 명령과 데이터베이스 정책 모두 소유자·학급 관계·역할·동의 조건을 확인해야 한다. 사용자가 수정 가능한 프로필 값이나 회원가입 폼의 역할 선택만으로 교사 권한을 부여하지 않는다. 공개 목록과 학생 데이터의 접근 경로를 분리한다.

## 5. 상태와 변경 불가능한 기록

### 초안

- 초안은 계속 편집할 수 있는 작업 공간이다.
- 저장 시 기대한 revision과 현재 revision이 일치해야 한다. 불일치하면 충돌을 알리고 다른 기기에서 저장한 내용을 덮어쓰지 않는다.
- 최초 revision 및 증가 규칙은 서버 계약으로 고정한다.
- ‘저장 중’, ‘저장 완료’, ‘저장 실패’를 실제 저장 결과에 맞게 표시한다. 설정이 없거나 저장에 실패했을 때 가짜 성공을 표시하지 않는다.

### 학습 제출본

- 제출 시 제목·본문·작성자·배정·버전·제출 시각을 포함하는 스냅샷을 만든다.
- 제출 내용은 수정·덮어쓰기 불가다. 이후 수정은 새 버전으로 남긴다.
- 검토 상태는 `submitted → revision_requested 또는 completed`다. 새 버전을 제출하면 그 버전은 `submitted`로 시작한다.
- 초안 상태와 제출본의 검토 상태는 별도다. 학생이 수정 초안을 쓰는 동안 기존 검토 대상이 사라지지 않는다.
- 피드백은 특정 제출 버전에 연결한다. ‘수정 요청’에는 구체적인 피드백이 필요하다.
- 수정형 미션의 완료는 이전 초고, 피드백, 내용이 달라진 후속 제출본을 확인해야 한다. 일반 질문·글쓰기 미션에 수정 과정을 모두 강제하지 않는다.
- 완료 뒤 학습용 글을 고치는 것만으로 완료 기록·배지를 자동 취소하지 않는다. 재검토가 필요하면 새 버전을 제출한다.

### 대회 출품본

- 미션 완료·대회 출품·작품 공개는 서로 다른 행동이다.
- 학생이 명시적으로 선택한 완료 제출본의 별도 사본을 출품본으로 보관한다.
- 대회 마감 전 출품본 교체를 지원한다면 이전 버전을 덮어쓰지 않고 교체 이력을 남겨야 한다. 초기 화면에서 교체를 지원하지 않으면 해당 제한을 제출 전에 알린다.
- 마감 이후 신규 출품·심사본 교체를 서버에서 차단한다.
- 학습 제출본을 이후 수정해도 출품 내용은 바뀌지 않는다. 심사는 고정된 출품본을 대상으로 한다.
- 작품과 공개용 표시에 이름·학교 등 식별 정보가 섞이지 않는지 검토하는 운영 절차를 별도로 마련한다.

## 6. 요구사항과 수용 기준

| ID | 요구사항 | 수용 기준 |
| --- | --- | --- |
| CAT-01 | 미션 목록·검색 | 18개 활동을 제공하며 주제·학년군으로 좁힐 수 있다. 검색 결과가 없으면 빈 상태를 안내한다. 각 상세 화면에서 질문·단계·예상 시간·수정 필요 여부를 확인할 수 있다. |

| AUTH-02 | 교사 권한 | 학생이 프로필 값을 바꾸거나 요청을 조작해 교사 기능을 실행할 수 없다. 실제 교사 권한 확인·승인 절차가 마련되기 전 학생 대상 운영을 시작하지 않는다. |
| CONSENT-01 | 참여 조건 | 유효한 동의·참여 조건이 확인되지 않은 학생의 학급 참여와 글 저장·제출 등 학생 데이터 처리를 차단한다. 동의 확인 방식과 철회 대응은 출시 전에 확정·검증한다. |
| CLASS-01 | 학급·배정 | 담당 교사만 자기 학급에 미션을 배정한다. 학생은 자신이 실제로 참여한 학급의 활동만 볼 수 있다. |
| WRITE-01 | 입력 검증 | 제목 1~100자, 본문 1~10,000자를 검증한다. 앞뒤 공백을 정리하고 공백만 있는 글·문자열이 아닌 입력을 거부한다. 초안 저장 규칙은 최종 제출 검증과 구분할 수 있다. |
| WRITE-02 | 초안 충돌·저장 상태 | 오래된 revision으로 저장하면 기존 내용을 덮어쓰지 않는다. 성공 응답을 받은 뒤에만 저장 완료로 표시한다. 빈 초안을 허용한다면 제출 시에는 별도로 유효성을 검사한다. |
| SUB-01 | 불변 제출 버전 | 제출 뒤 초안을 고쳐도 제출본 내용은 그대로다. 재제출은 새 버전이며 이전 피드백을 읽을 수 있다. |
| SUB-02 | 요청 재시도 | 같은 제출 요청 식별자를 재전송해도 제출본·완료 기록·배지가 중복 생성되지 않는다. 식별자가 같은데 내용이 다르면 기존 요청과 충돌함을 알린다. |
| REVIEW-01 | 피드백·수정 | 담당 교사만 대상 버전을 검토한다. 수정 요청에는 피드백이 필수다. 수정형 미션은 피드백 이후 바뀐 내용의 재제출 없이는 최종 완료 처리되지 않는다. |
| REVIEW-02 | 업무량 | 교사는 검토 대기·재제출·완료를 구분해 볼 수 있다. 단순 완료와 실제 피드백 제공을 구분한다. 일괄 처리·문구 템플릿은 제공 여부를 별도 백로그로 관리한다. |
| DEADLINE-01 | 두 종류의 마감 | 기본 미션의 늦은 제출은 허용하되 표시한다. 대회 마감은 서버 시각을 기준으로 차단한다. 화면에 표시하는 날짜·시간은 Asia/Seoul 기준이다. |
| CONTEST-01 | 선택 출품 | 완료 작품 중 학생이 출품 대상을 명시적으로 고른다. 미참가가 미션 완료·학습 배지에 영향을 주지 않는다. 대회 범위·참가 자격·학급 관계를 서버에서 검사한다. |
| CONTEST-02 | 고정된 심사본 | 출품 후 원본 글을 바꾸거나 재제출해도 심사본은 그대로다. 동일 출품 요청 재시도로 중복 출품하지 않는다. |
| CONTEST-03 | 심사 | 사전에 안내한 기준으로 고정된 출품본을 평가한다. MVP의 교사 심사는 전국대회용 익명·다중 심사 체계가 완성되었다고 표현하지 않는다. |
| BADGE-01 | 근거 있는 보상 | 예를 들어 첫 완료·첫 수정 완료처럼 확인 가능한 행동에 한해 지급한다. 같은 사건에 중복 지급하지 않고 획득 이유를 표시한다. 접속·글 길이·대회 참가만으로 학습 품질을 판단하지 않는다. |
| PRIVACY-01 | 기본 비공개 | 학생 초안·제출본·피드백은 해당 학생과 담당 교사만 접근한다. 공개 전시·학급 공유에는 별도 절차가 필요하다. 분석·로그에 작품 본문·피드백 전문·특권키를 남기지 않는다. |
| UX-01 | 오류·접근성 | 저장·제출 실패와 설정 누락을 성공처럼 표시하지 않는다. 입력에 명확한 레이블을 제공하고 키보드 조작·모바일 화면을 확인한다. 오류 안내에서 학생 데이터나 내부 비밀을 노출하지 않는다. |
| OPS-01 | 검증·운영 준비 | 타입 검사·동작 테스트·프로덕션 빌드를 통과한다. 로컬 성공을 실제 Supabase·Vercel 운영 검증 완료로 표현하지 않는다. |

## 7. 배지와 게임 요소

초기에는 탐험 지도, 주제별 활동, 완료 기록, 간단한 배지를 제공한다. 배지는 경쟁 점수보다 수행한 행동을 설명한다. ‘첫 미션 완료’는 교사의 첫 완료 처리, ‘첫 수정 완료’는 피드백 이후 변경된 글의 재제출과 완료 처리처럼 서버에서 확인 가능한 사건을 기준으로 한다.

유료 아이템에 따른 학습 점수 우대, 접속 중단 벌점, 확률형 현금성 보상, 학생별 공개 순위는 초기 범위에 포함하지 않는다. 학생이 활동을 선택하고 자기 이전 기록을 돌아보는 흐름을 우선한다.

## 8. 데이터와 기술 경계

- **Next.js:** 공개 미션 탐색과 인증 후 학생·교사 화면, 서버 입력 검증과 명령 처리.
- **Supabase:** 인증, 학급 관계, 초안, 불변 제출 버전, 피드백, 대회 심사본, 보상 및 운영 기록. 데이터 접근 정책으로 권한을 강제한다.
- **GitHub:** 변경 이력, 검토 가능한 작업 단위, 자동 검사. 원격 저장소 생성·연결 여부는 실제 실행 결과로 판단한다.
- **Vercel:** 검증 가능한 배포와 환경 설정. 운영 배포 전에 실제 대상 계정·프로젝트·환경을 확인한다.
- **Codex:** 요구사항에 따른 구현과 검증을 돕는다. 교육적 품질 판정, 교사 자격 확인, 동의 확보를 대신 완료했다고 간주하지 않는다.

브라우저에 Supabase 특권키를 넣지 않는다. 화면에 노출되는 환경 변수와 서버 전용 비밀을 구분한다. 잘못된 저장소·프로젝트에 원격 쓰기를 수행하지 않는다. 테스트는 합성 데이터로 시작한다.

## 9. 시범 운영 측정

의미 있는 사건은 `draft_saved`, `submission_created`, `feedback_created`, `revision_submitted`, `submission_completed`, `contest_entered`, `entry_reviewed`처럼 실제 서버 처리 결과를 기준으로 정의한다. 구현 시 이벤트 이름이 달라지면 이 정의와 매핑한다.

이벤트에는 내부 사용자·학급·미션 식별자, 대상 버전, 서버 발생 시각, 중복 방지 식별자를 둔다. 작품 본문·피드백 전문을 분석 이벤트에 복사하지 않는다. 자동 저장 횟수와 페이지 방문 수는 학습 성취 수치로 사용하지 않는다.

| 지표 | 정의 |
| --- | --- |
| 시작률 | 초안을 한 번 이상 저장한 학생 수 / 배정 학생 수 |
| 제출률 | 유효 제출 버전이 있는 학생 수 / 배정 학생 수 |
| 수정 경험률 | 피드백 이후 달라진 버전을 제출한 학생 수 / 피드백을 받은 학생 수 |
| 수정 학습 완결률 | 초고·피드백·수정·완료를 모두 경험한 학생 수 / 수정 활동 대상 학생 수 |
| 다음 주 활동 유지율 | 기준 주 활동 학생 중 다음 주에도 초안 저장·제출·수정 제출을 한 학생 수 / 기준 주 활동 학생 수 |
| 교사 응답 경과 시간 | 제출부터 피드백 또는 완료 처리까지의 경과 시간. 실제 교사 작업 시간과 구분 |
| 선택 출품률 | 자발적으로 출품한 학생 수 / 대회 참가 자격 학생 수. 낮은 비율을 학습 실패로 단정하지 않음 |
| 운영 오류 | 제출·저장 실패, 중복, 심사 누락, 권한 차단 관련 오류와 해결 상태 |

지표의 목표 수치는 시범 운영으로 기준선을 확보한 뒤 결정한다. 글자 수 증가를 표현 능력 향상으로 단정하지 않으며, 작품의 변화는 같은 기준표를 사용한 교사의 표본 검토로 살핀다.

## 10. 실제 학생 대상 출시 차단 조건

다음 항목이 해결되지 않았다면 실제 학생을 초대하거나 실제 학생 글을 수집하는 운영 출시를 완료로 표시하지 않는다.

1. 교사 역할 확인·발급·회수 절차와 담당 학급 경계가 검증되어야 한다.
2. 아동 참여에 적용할 개인정보 처리·동의 요건을 확인하고, 보호자 등 필요한 동의의 확인·기록·철회 흐름을 마련해야 한다. 개발용 동의 플래그나 교사의 임의 체크만으로 절차 완료를 주장하지 않는다.
3. 수집 항목·보관 기간·삭제·탈퇴·문의·학생 작품 공개 및 철회 절차를 실제 운영 주체가 확정해야 한다.
4. 실제 Supabase 환경에서 학생 간·학급 간 접근 차단, 동의 미확인 접근 차단, 특권키 비노출, 불변 버전, 재시도·마감·충돌을 검증해야 한다.
5. 실제 배포 환경에서 인증·로그아웃·재로그인·오류 처리·모바일 사용을 확인해야 한다. 로컬 메모리 DB 테스트는 운영 환경 검증의 대체가 아니다.
6. 콘텐츠·심사 기준·신고 대응·문제 작품 처리와 교사 업무량을 운영 담당자가 확인해야 한다.

이 항목은 제품의 출시 조건이며, 특정 법률에 대한 적법성 보증이 아니다. 현재 문서는 서비스 배포, 계정 연결, 동의 확보 또는 법적 검토의 완료를 주장하지 않는다.
