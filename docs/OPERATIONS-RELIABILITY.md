# 장애·복구, 교사용 현황·알림, 기록 검색

> 2026-11-02 최신 운영 설명은 [OPERATIONS-EIGHT.md](OPERATIONS-EIGHT.md)를 우선합니다. 아래 과거의 미완료·미설정 표기는 당시 이력입니다.

구현·검증일: 2026-11-01. 실제 계정용 `/hub`와 `/status`의 추가 기능이다. `/studio`의 브라우저 체험 기록과 연결하지 않는다.

## 1. 연결과 글 복구

- `/status`는 장애 중에도 열 수 있는 연결 점검 화면이다. DB와 로그인 서비스에 실제 요청을 보내며, 설정 값이 있다는 이유만으로 정상 표시하지 않는다. `/api/health?deep=1`은 두 점검이 성공할 때만 HTTP 200, 나머지는 503을 반환한다. 공개 점검은 학생 글이나 계정을 조회하지 않는다.
- `.github/workflows/availability.yml`이 main 푸시·수동 실행·매시 17분 예약으로 공개 주소를 점검한다. 배포 전환·일시 장애에 최대 약 2분간 재시도하고 실패 시 Actions 작업을 실패시킨다. 예약은 GitHub 사정에 따라 늦어질 수 있다. 관리자의 GitHub 알림 설정에 따른 실패 알림을 사용하며 메일·메신저에 학생 정보를 보내지 않는다.
- `/status`에서 최근 자동 점검 이력을 조회한다. 읽기 실패나 3시간 넘게 지난 결과를 정상으로 포장하지 않는다. Next 오류 계측은 오류 종류·시각만 기록하며 예외 원문·요청 URL·헤더·본문·학생 글을 직렬화하지 않는다.
- 인터넷 끊김·재연결을 안내하고, 원래 초안 저장 큐·서버 revision·제출 멱등성을 유지한다. 재연결 안내가 저장 성공을 뜻하지 않는다.
- 학생이 선택한 경우에만 미저장 글을 해당 탭의 `sessionStorage`에 최대 24시간 임시보관한다. 복구 글은 사용자·배정 ID를 모두 대조하고 자동으로 편집기를 덮어쓰지 않는다. 서버 버전이 달라지면 파일로 비교하도록 안내한다. ‘임시보관 후 서버 글 다시 확인’은 보관 성공을 확인한 뒤 화면을 다시 연다.
- 서버 저장 확인·명시적 삭제·로그아웃 때 임시보관을 제거한다. 같은 출처의 다른 탭에는 본문 없는 정리 신호를 보낸다. 브라우저가 저장을 차단하면 실패를 알리고 텍스트 파일 저장을 제공한다. 실물 기기의 강제 종료나 실제 통신망 단절을 보장하는 오프라인 편집기는 아니다.

## 2. 암호화한 학급 학습기록 보관

담당 교사가 `/status`에서 독서 기록·제출한 글의 모든 접근 가능한 버전을 내려받는다. **제출 전 학생 개인 초안은 학생 본인만 볼 수 있는 기존 RLS를 유지하므로 교사 보관 파일에 포함하지 않는다.** 계정 암호·토큰·거래 원장·Google 파일도 포함하지 않는다.

보관 암호는 12~200자이며 브라우저에서 PBKDF2-SHA256 210,000회·무작위 salt와 IV·AES-256-GCM으로 암호화한다. 암호와 복호화된 보관 파일은 업로드하거나 기기에 자동 저장하지 않는다. 파일은 승인된 별도 보관 장소에, 암호는 따로 보관한다. 암호 분실 복구 기능은 없다.

‘보관 파일 열기·검사’로 실제 복호화·형식·학급 일치·중복 검사를 거쳐 내용을 읽는다. 잘못된 암호·변조·다른 학급 혼합은 거부한다. 이는 사본을 다시 열어 확인하는 기능이며 현재 DB의 학생 글·불변 제출본을 덮어쓰지 않는다. 한 파일은 최대 20,000건·복호화 전 원문 8MB까지이며 넘으면 잘라 보관하지 않고 오류를 반환한다.

**DB 전체 재해 복구와 구분한다.** 전체 복구에는 Auth·원장·권한·운영 자료가 함께 필요하다. 프로젝트 요금제에 맞는 Supabase 백업과 외부 보관·별도 환경 복원 절차를 운영자가 준비해야 한다. 이번 변경에서 유료 백업/PITR 설정을 활성화하거나 운영 DB를 되돌리지 않았다. [Supabase 백업 안내](https://supabase.com/docs/guides/platform/backups)를 따른다.

## 3. 교사용 현황판과 알림

교사 홈과 `/hub?tab=overview`에 담당 학급별 참여 준비 인원, 미제출 활동 수, 기한 지난 미제출, 새 제출, 수정 대기, 완독 확인 대기를 표시한다. 미제출은 학생별 배정 활동 수이며 성취도·학교 출결 판정이 아니다. 비활성·동의 대기·첫 암호 변경 전 학생은 준비 상태를 표시하고 활동 집계에서 제외한다.

최신 제출 버전만 집계한다. 읽지 않은 새 글·완독·역할 신청/완료 보고·광장·전시 신청을 보여 주며 기록으로 이동한다. 알림 읽음은 학급별 시각을 단조 증가시키는 멱등 명령이다. 읽음 표시로 교사 검토·보수 지급·승인을 완료하지 않는다. 새 제출이나 새 완료 보고는 다시 읽지 않음이 된다. 본문은 알림 테이블에 복사하지 않는다. 실시간 푸시가 아니라 접속·새로고침 시점의 집계이며 갱신 시각을 표시한다.

학생별 표는 25명씩, 알림 목록은 최근 50건씩 표시하고 **전체 집계는 목록 제한과 분리**한다. 담당 학급 조건·학생별 검색 이동·기록 확인함·수업 꾸러미·학급 준비로 연결한다.

## 4. 서버에서 전체 기록 검색

`/hub?tab=search`에서 학급·학생·기록 종류·상태·날짜·검색어를 조합한다. 학생은 자기 독서·초안·제출 버전, 교사는 담당 학급의 독서·제출 버전만 검색한다. 모든 제출 버전을 구분해서 표시한다. 원본 테이블의 RLS를 보존하는 SECURITY INVOKER 뷰·RPC를 사용하며 익명 조회·교차 학급·교사 간 접근을 차단한다.

서버가 조건을 적용한 후 정확한 전체 수와 25건씩의 페이지를 반환한다. 기존 100/500/1,000개 화면 상한에 검색 결과를 맞춰 잘라내지 않는다. `%`·`_`·역슬래시를 검색 문자의 의미로 취급하며 한글 부분 문자열을 찾는다. 복잡한 형태소 검색 엔진은 아니다. 날짜·학급·학생 인덱스를 추가했고 대규모 동시 접속 성능은 별도 검증 대상이다.

검색한 기록은 펼쳐 읽고 Word 사본으로 저장할 수 있다. 제출한 글은 교사 확인함 또는 학생 미션·피드백 화면으로 연결한다. 페이지를 바꾸어도 검색 조건을 보존한다.

## 확인한 범위

- 자동 검사는 RLS·익명/다른 교사 거부, 개인 초안 비공개, 최신 버전 집계, 읽음 시각과 새 보고, 1,031건의 전체 검색·정확한 페이지, 날짜/문자 조건, 암호화·복호화·변조/오인 암호 거부, 임시 글의 본인/배정/만료, 로그아웃 정리와 실제 연결 판정을 포함한다.
- 실제 Supabase에 표시된 가상 계정으로 학급·학생 발급·동의 제한·읽기/쓰기/보상 흐름을 실행했다. 실제 학생 또는 보호자 동의는 사용하지 않았다.
- 가상 과거 독서 1,027건을 넣어 브라우저 조건 검색·2페이지·42페이지의 마지막 두 건과 Word 내보내기 내용을 확인했다.
- 실제 브라우저에서 임시보관 → 서버 글 다시 확인 → 임시 글 불러오기 → 서버 저장을 확인했다. 다른 요청이 서버 버전을 높이면 임시 글 불러오기를 막고 최신 글을 보존했다.
- 학급의 독서·제출 1,032건을 실제 암호화 다운로드 → 파일 선택 → 복호화/검사 → 본문 읽기로 대조했다. 파일에 학생 이름·본문 평문이 없었고 잘못된 보관 암호는 거부됐다.
- 실제 Next API에서 DB/Auth 점검 성공, private/no-store 보관 응답, 학생·타 학급 교사·외부 Origin 거부를 확인했다. 최종 배포·자동 점검·가상 자료 정리는 `VERIFICATION.md`의 최신 기록을 따른다.

마이그레이션은 원격 이력과 일치하는 `20261101141825_reliability_overview_search.sql`이다. 새 읽기 뷰는 SECURITY INVOKER이고 알림 시각의 직접 쓰기는 회수했다. 보안 Advisor의 기존 비공개 RLS INFO 3건·기존 및 인가된 SECURITY DEFINER 주의 18건·기존 유출 암호 보호 미활성 주의는 남는다. 직접 쓰기·역할·담당 학급 검사를 별도로 통과했으며 무경고 상태로 보고하지 않는다.
