# 캐릭터 성장·꾸미기와 학기 종료·진급

2026-11-02. 실제 학교 운영과 구별한 가상 계정으로 검증한다.

## 학생의 성장

- 캐릭터·배지에서 토끼·여우·부엉이를 선택하고, 실제 활동 경험치에 따라 네 가지 모습으로 성장한다. 성장 기준은 0 / 50 / 450 / 1,250 XP이며 기존 레벨 계산을 따른다.
- 성장 장식·배경 6종과 학급 상점 장식·배경 3종을 제공한다. 액세서리와 배경을 미리 본 뒤 저장한다. 성장 보상은 경험치, 상점 보상은 지급 완료된 주문 근거를 서버가 확인한다. 작가 모자는 200 XP도 필요하다.
- 예약·취소 주문은 착용 권한을 주지 않는다. 동일한 장식의 중복 예약·구매를 막고, 지급 재시도는 보유품을 중복 생성하지 않는다.
- 다른 창의 수정은 장비 revision으로 충돌을 알린다. 다른 내용으로 같은 요청 ID를 쓰면 거부한다. 승인된 기록 삭제로 획득 근거가 없어지면 유효한 기본 모습으로 표시한다.

## 학기 운영 순서

1. **학기 종료·진급**에서 실제 학년도·학기·학년을 저장한다. 기존 학급에 임의의 학기를 일괄 지정하지 않는다.
2. 마무리 전 확인에서 제출·고쳐쓰기·독서 확인·역할·글쓰기 활동·주문 현황을 확인한다. 예약 주문은 지급 또는 취소 후 종료한다. 다른 미완료 활동은 현재 상태로 보관한다.
3. 종료 안내를 확인하고 학기를 보관한다. 기록 조회·검색·내보내기를 유지하되, 기존 함수와 직접 호출에서도 새 기록·피드백·구매·보상 변경을 차단한다. 초대 코드는 종료되며, 다시 열어도 자동 부활하지 않는다. 동의 철회·승인된 기록 삭제는 계속 가능하다.
4. 종료된 학급에서 다음 학기를 지정하고 진급할 학생을 직접 선택한다. 최대 100명씩 준비한다. 화면 명단은 최대 200명이며 초과 시 표시된 제한을 확인한다. 같은 학생을 같은 다음 학기로 중복 준비하지 못한다.
5. 새 학급은 현재 교사 소유로 생성된다. 운영자의 기존 **학급 인계**로 다음 담임에게 넘길 수 있다. 다른 교사의 이메일이나 명단을 임의로 검색·공개하지 않는다.
6. 새 학급의 동의 자료를 등록하고 운영자 승인을 받은 뒤 교사가 학생별 **이 학급에서 시작**을 누른다. 지난 학급의 동의나 단순한 참여 승인만으로 이 단계를 우회할 수 없다.

기존 Auth 계정·비밀번호·경험치·장식은 유지한다. 글·과제·화폐·그룹은 복사하지 않는다. 화폐는 학급마다 별도이며 새 학급은 0에서 시작한다. 기존 관리 학급에서 진급한 학생의 비밀번호 재발급 권한은 시작 시 새 관리 학급으로 옮긴다. 여러 학급에 참여하는 학생의 다른 관리 학급을 임의로 덮어쓰지 않는다. 이전 담임의 기록 권한과 새 담임의 계정 관리 권한은 각각 자신의 학급으로 제한된다.

## 데이터와 권한

마이그레이션: `20261101145929_character_semester_progression.sql`. 카탈로그·보유품·착용 상태·진급·참여 확인·학기 운영 이력을 RLS로 보호하며, 인증된 사용자도 테이블 직접 변경은 할 수 없다. 권한 검사·재시도·학기 revision·행 잠금을 거친 명령만 허용한다. 실제 동의 승인 권한은 기존 운영자 절차를 유지한다.

학급 기록 삭제는 그 학급의 획득 근거와 기록을 삭제한다. 다른 학급의 참여 확인은 유지한다. 새 학급 기록을 삭제한 경우 최소한의 진급 연결을 남겨 동의 승인 없는 재가입을 막으며, 계정 전체 삭제 시 보유품·착용·진급 참여 기록도 함께 삭제한다. 실명·학생 글·비밀번호는 로그에 기록하지 않는다.

## 검증 근거

- TypeScript 검사와 프로덕션 빌드, 전체 Vitest 330개 통과. 새 DB 검사 13개와 도메인 검사 4개 포함.
- 실제 Supabase의 가상 교사·학생으로 계정 발급·첫 비밀번호 변경·동의 승인·독서 확인·초안·제출·고쳐쓰기·보상·상점 흐름을 먼저 점검했다.
- 로컬 프로덕션 UI에서 장식 상품 등록, 학기 정보 설정, 종료, 학생 선택 진급, 새 학급 참여 시작, 학생 꾸미기 저장을 수행하고 실제 DB의 결과를 다시 확인했다.
- 실제 DB에서 예약 중 착용 거부, 중복 구매 거부, 미지급 주문의 학기 종료 차단, 종료 후 이전 기록 수정 거부, 새 학급 동의 필요, 계정·경험치·장식 유지, 별도 지갑, 새 학급 글 제출, 담임 인계와 비밀번호 재발급 권한 분리를 확인했다.
- 가상 학생은 75 XP / 목도리 착용을 유지하고, 보관 학급 지갑 12개 / 새 학급 지갑 0개로 시작했다. 실제 학교의 보호자 동의나 학생 사용 승인을 의미하지 않는다.
- Supabase 보안 점검의 새 공개 명령 3개는 함수 내부 인증·권한 검사와 익명 실행 금지를 검증했다. private 재시도 테이블은 직접 접근을 막는 기본 거부 RLS이다. 기존 유출 비밀번호 보호 비활성 경고는 이번 기능의 변경 대상이 아니다.

공개 서버에서도 인증된 학생 성장·학기 화면과 교사 참여 화면, 보관 기록·글의 Word·CSV 내용, 심층 연결 점검을 확인했다. 새 기능의 실제 서버·UI 검증은 30건이다. 가상 학생을 제품의 승인 삭제로 제거한 뒤 정확한 표식·UUID·소유자 검사로 가상 교사와 빈 학급도 정리했다. 기존 운영자 1명은 유지하며, 가상 장식·진급 참여·운영 이력이 남지 않음을 확인했다. 배포·CI 근거는 [검증 기록](VERIFICATION.md)에 남긴다.

실제 교실·학생 기기·대규모 동시 사용·학교 운영자의 업무 검수는 별도 운영 검증이다.
