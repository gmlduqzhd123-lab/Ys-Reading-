# 운영 개선 8가지 · 2026-11-02

> 이후의 예약 백업·복구·공동교사·보고서 검토·기기 점검 변경은 [2026-11-04 운영 확대](OPERATIONS-2026-11-04.md)를 따릅니다. 아래 내용은 기존 기능의 이력입니다.

이 문서는 이번 개발 묶음의 현재 기능과 운영 방법을 설명합니다. 이전 날짜의 백로그·설정 문서는 개발 당시의 이력입니다. 실제 실행 증거는 VERIFICATION.md의 최신 기록을 우선합니다.

1. **장애 감시·복구 알림**: Supabase Cron이 5분마다 공개 HTTPS의 실제 DB·Auth 연결을 검사합니다. 결과는 다음 주기에서 수집하며 12분 넘게 신호가 없으면 오래된 결과로 표시합니다. 장애 기간을 하나의 사건으로 모으고 회복 시 닫습니다. 앱의 접속 중 알림과 `/status`에서 확인합니다. GitHub의 20분 간격 점검은 별도 보조 채널이며 지연될 수 있습니다. 앱을 닫은 사용자의 휴대전화 푸시나 외부 메일을 발송하는 기능은 아닙니다. 새 복구 환경에서는 `scripts/setup-service-monitor.sql`을 프로젝트 소유자로 적용합니다.
2. **암호화 백업 자동화**: `powershell -NoProfile -File scripts/Install-Operator-Backup.ps1`은 현재 사용자 전용 `\Bookforest\Bookforest-Operator-Backup` 작업을 매일 19시 및 Windows 로그인 시 실행합니다. 현재 운영자 PC에 설치했습니다. PC 전원·사용자 로그인·Codex의 Supabase 인증이 필요합니다. 성공·실패를 기록하고 통신 실패 시 로컬 실패 기록을 다음 연결 때 전달합니다. 검증된 90일 초과 보관 파일은 최신 7개를 남기고 정리합니다. 다른 저장 위치의 복사본은 별도 관리해야 합니다.
   - 복구 키 내보내기: `node scripts/operator-recovery-key.mjs export --file=전체경로.bfkey`. 도구가 묻는 20자 이상 별도 암호를 직접 입력합니다. 파일은 현재의 운영자 보관 폴더에 생성됩니다. 암호화 키 파일과 백업을 다른 안전한 장치에도 복사하고 암호는 따로 보관합니다. 채팅·Git·로그에 키 또는 암호를 보내지 않습니다.
   - 새 PC: 승인된 백업 폴더를 준비하고 `node scripts/operator-recovery-key.mjs import --file=전체경로.bfkey`로 키를 해당 Windows 사용자의 DPAPI로 다시 보호합니다. 다른 기존 키를 덮어쓰지 않습니다. 이후 `node scripts/operator-backup.mjs --verify=전체경로.bfbak`로 검사합니다.
   - 격리 복원 검사는 별도 PostgreSQL 엔진에서 실제 스키마·데이터·행 내용·외래키·RLS를 확인합니다. 새 Supabase 프로젝트로 Auth API·이메일·OAuth·환경 변수까지 연결하는 재해 복구 전환은 별도 운영 훈련입니다. 운영 DB를 되돌리거나 유료 PITR을 켜지 않습니다.
3. **운영자 2단계 인증**: `/account/security`에서 본인의 인증앱을 등록하고 직접 확인합니다. 학생 동의 승인·철회, 삭제 승인·계정 삭제 실행, 교사 권한·계정 상태·담임 인계·보관 정책 변경은 최근 15분 이내 AAL2 인증이 필요합니다. 오래된 인증과 완료 요청 재전송도 다시 검사합니다. QR·OTP를 채팅에 보내지 않습니다. 모든 인증 기기를 잃으면 프로젝트 소유자의 별도 본인 확인·Supabase 관리 절차가 필요합니다. 유출 비밀번호 보호는 Supabase의 Pro 이상 기능이므로 비용 승인 없이 요금제를 변경하지 않습니다.
4. **운영 명단 페이지 처리**: 학생·동의·삭제·운영 이력을 각각 50개씩 읽고 정확한 전체 수를 반환합니다. 검색은 서버에서 적용하며 `%`도 문자로 처리합니다. 오늘 할 일·다른 탭의 본문을 불필요하게 읽지 않습니다. 학급 생성 화면은 학습 기록 대신 명단 수와 아이디만 읽습니다. 학급/교사/학년 모임 설정 목록은 최대 1,000개이며 학교 전체 대규모 동시 접속 성능을 보장하는 부하 검사는 별도입니다.
5. **학생 계정 발급 재개**: 새로고침 뒤에도 담당 교사의 원래 작업에서 이름·아이디·완료 여부를 불러올 수 있습니다. 이미 완료한 계정은 건너뛰고 미완료 계정만 새 초기 비밀번호로 이어갑니다. 기존 안내표의 비밀번호는 서버에서 복원하지 않습니다. 안내표를 잃은 완료 계정은 별도의 비밀번호 재발급 절차를 이용합니다. 중단 직전 Auth만 생성된 계정은 원래 작업·학생 상태를 확인한 경우에만 복구하며 학생이 변경한 비밀번호는 덮어쓰지 않습니다.
6. **실제 서비스 통합 CI**: `browser-journey.yml`은 GitHub의 격리된 Docker Supabase Auth·PostgreSQL·Edge와 Next를 사용합니다. 합성 계정으로 MFA·동의·독서·글쓰기·교사 검토·보상·경제·보고서·내보내기를 Chromium에서 검사하고 공개 화면은 WebKit 휴대전화 크기로 검사합니다. 운영 URL·키로 실행하지 못하도록 주소를 검사합니다. 자격 증명·추적 파일·학생 글을 CI 산출물로 올리지 않습니다. 실제 학교 PC·태블릿·학교망·일반 학교 Google 계정은 별도 현장 확인이 필요합니다.
7. **개인정보 운영**: `/account/records`에서 담당 학급의 학교 보관 근거·기간을 확인한 이력을 남깁니다. 신규 내보내기는 원문 없이 종류·생성 시각·형식·사본 링크를 본인에게만 기록합니다. 보관 근거·다음 확인일·실제 정리 확인을 갱신할 수 있습니다. 다운로드 성공이나 Drive/PC 파일 삭제를 자동으로 단정하지 않습니다. 원본 삭제와 이미 만들어진 외부 사본·운영자 백업 폐기는 별도로 처리합니다. 이 기능은 기관의 동의·법정 보관 기준을 대신 결정하지 않습니다.
8. **학기 성장 보고서**: `/reports`에서 학급·학생·기간을 고르고 완료 대표 작품 최대 3편·처음 제출한 글·사실 수치·교사의 관찰 의견을 모읍니다. 교사의 명시적 검토 확인 후 불변 판으로 저장하고 학생 공개 여부를 선택합니다. 학생은 참여 중인 학급의 본인 공개 판만 읽습니다. Word·CSV·인쇄/PDF와 연결한 교사의 Google Docs/Sheets 사본을 만들 수 있습니다. 재제출 횟수는 실력 향상 점수가 아니며 책숲 출석은 학교 출결과 다릅니다.

Google OAuth 앱은 기존 사용자 승인에 따라 일반 공개(Production)로 게시되었습니다. 별도 학교의 외부 앱 정책이나 미사용 교사 계정의 실제 동의를 대신 검증한 것은 아닙니다. 기존 기본 운영자 계정은 보존하며 실사용 학생·보호자의 자료를 개발 시험에 사용하지 않습니다.

## 실제 확인 결과와 인계 사항

- 타입 검사·39개 파일의 자동 검사 372개·프로덕션 빌드를 통과했습니다. 격리 Supabase를 사용하는 브라우저 검사 6개에서는 실제 Auth·MFA·동의·독서·글쓰기·검토·경제·보고서·Word 다운로드와 Chromium PDF 생성, WebKit 휴대전화 크기의 공개 화면을 확인했습니다.
- 실제 Supabase의 일부 완료/일부 Auth만 생성된 중단 작업을 브라우저에서 재개했습니다. 원래 완료 계정의 비밀번호는 유지되고 새로 완료한 한 명만 안내표에 포함됐으며, 그 비밀번호로 실제 로그인을 확인했습니다.
- 기존 운영자 본인이 새 인증앱 등록과 확인을 완료했습니다. 등록된 정상 인증 수단 1개와 미완료 수단이 없는 상태를 확인했습니다. 사진에 포함됐던 준비용 값 대신 새 등록을 사용했습니다.
- 실제 공개 서비스에서 보고서의 Word·인쇄 원문을 확인하고 Google Docs/Sheets를 각각 생성했습니다. 내려받은 문서·시트 본문에서 활동 수치·관찰 의견·초고·최종 글을 대조하고 ‘나에게만 공개’ 상태를 확인했습니다. 검증 자료는 모두 가상입니다.
- Windows 예약 작업의 실제 실행 종료 코드 0과 암호화·격리 복원 성공을 확인했습니다. Node·Codex의 실행 경로를 명시하고 창을 숨겨 실행합니다. 백업 도중 프로세스가 종료되면 다음 실행은 실제 PID가 살아 있는지 확인해 고아 잠금을 복구하며, 살아 있는 백업의 잠금은 오래됐더라도 빼앗지 않습니다. Codex 업데이트 또는 프로젝트 폴더 이동 후에는 설치 도구를 다시 실행해 경로를 갱신하세요.
- 가상 학생 3명을 승인 삭제하고 같은 삭제 요청을 재전송해 안전하게 완료됨을 확인했습니다. 가상 교사 3명·학급 2개를 소유자·표식·UUID 조건으로 정리했습니다. 실제 사용자·운영자는 각각 1명이고 학급·독서·제출·원장·성장 보고서는 0건입니다. 실제 운영자의 인증앱과 Google 연결은 보존했습니다. 검증용 비공개 Google 사본은 원본 삭제와 독립된 사본의 예로 보관돼 있습니다.
- 복구 키 내보내기/가져오기는 별도 암호를 이용하도록 구현하고 암호화·오인 암호·변조 거부를 검사했습니다. 운영자 본인의 복구 암호 선택, 다른 장치로의 키·백업 복사, 다른 PC와 별도 Supabase 프로젝트에서 Auth/OAuth까지 전환하는 훈련은 자동 수행하지 않았습니다. 실제 학교 기기·학교망과 대규모 부하 확인도 별도입니다. [Supabase의 유출 암호 보호](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)는 현재 비활성이며 비용 승인 없이 요금제를 변경하지 않았습니다.
