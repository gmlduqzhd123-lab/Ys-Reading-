# 책숲 장애 복구

1. 운영자 PC에서 예약 백업의 최근 성공 시각과 복호화·복원 검사 결과를 확인합니다.
2. PowerShell에서 `scripts/Recovery-Kit-Window.ps1`을 실행합니다. 외부 보관 폴더를 선택하고 본인만 아는 20자 이상 암호를 입력합니다. 채팅에 암호를 보내지 않습니다. 콘솔 방식은 `scripts/Prepare-Recovery-Kit.ps1`입니다.
3. 만들어진 암호화 폴더를 승인된 외부 장치에 복사합니다. 암호는 별도 장소에 보관합니다. 동일 PC 폴더에 생성한 것만으로 외부 보관 완료로 판단하지 않습니다.
4. 다른 PC의 동일 소스와 Node 환경에서 `scripts/Prepare-Recovery-Kit.ps1 -Mode verify`를 실행합니다. 복구 폴더와 암호로 검증합니다. Linux에서도 같은 검증 모듈은 DPAPI 없이 실행할 수 있습니다.
5. 이 검증은 데이터·함수·권한·외래키를 격리 PostgreSQL에 복원합니다. 실제 Supabase Auth 서비스와 Google 연결 전환은 다음 항목을 별도로 확인합니다.

| 전환 항목 | 통과 조건 |
|---|---|
| 새 Supabase 대상 | 운영과 다른 프로젝트임을 확인하고 비용·데이터 반입 승인 |
| Auth | 가입 차단, 이메일/Google 제공자, Site URL, 허용 콜백 복원 |
| 운영자 | 새 로그인 후 인증앱 재등록, 기존 세션 폐기, 최근 2단계 인증 |
| 학급 권한 | 담임·공동교사·학생 각각 로그인하여 다른 학급 접근 거부 확인 |
| Google | 비밀키를 별도 보관소에서 등록, 새 콜백 승인, 교사별 재연결 |
| Drive 파일 | DB 백업에 포함되지 않은 실제 파일의 별도 보관·공유 범위 확인 |
| Vercel | 새 프로젝트 URL·서버 비밀값 설정, CI 통과 후 도메인 전환 |
| 원장 | 잔액·원장 합계·중복 지급 방지·보상 재시도 확인 |

학교 기기 검사나 실제 새 서버 전환을 하지 않았다면 완료로 기록하지 않습니다. GitHub CI는 합성 계정만 사용하며 실제 운영 백업·암호·MFA 비밀값을 업로드하지 않습니다.
