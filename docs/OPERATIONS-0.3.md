## 백업과 복원의 구분

- 서버에는 공개키만 등록합니다. 일회용 작업은 10분 유효하고 한 번 소비됩니다. 업로드·읽기 대조를 DB 복원 성공으로 표시하지 않습니다.
- 운영자 PC에서 최신 서버 파일의 해시·복호화·별도 PostgreSQL 복원·최신 개인정보 대조를 검사하고 **그 파일에** 검증 시각을 연결합니다. 이전 파일의 검증으로 새 파일 성공을 표시하지 않습니다.
- 기존 복구 키에서 별도 ECDH 키를 파생하므로 새 비밀키를 서버에 올리거나 복구 묶음에 추가할 필요가 없습니다. 다른 PC에는 기존 `recovery.bfkey`와 본인이 별도 보관한 복구 암호가 필요합니다.
- 비공개 Storage는 DB와 **같은 Supabase 프로젝트**입니다. PC와 독립적이며 제공자 전체 장애·프로젝트 삭제에 대비하는 다른 제공자 사본과 실제 운영 전환은 별도입니다. 바탕화면 폴더는 같은 PC 사본으로 계속 구분합니다.
- 최신 7개는 유지하고 나머지 중 90일 초과 파일만 정리합니다. 내보내기 목록은 7일 후 매시간, 다운로드용 일회용 작업은 하루 후 정리합니다.
- GitHub 백업 알림에서 독립 서버 백업도 검사합니다. 기존 복원 검증 백업의 48시간 기준을 암호문 생성 성공으로 덮어쓰지 않습니다.

## 도구

- 서버 공개키 등록: `node scripts/operator-cloud-backup.mjs setup` (기존 운영자 보호 키 사용)
- 서버 파일 복원 검사: `node scripts/operator-cloud-backup.mjs --force`
- 새 서버 백업: 운영자 `/status`의 ‘서버 예약 작업에 새 백업 요청’ (최근 MFA)
- 기존 PC 백업·사본·설정 도구는 유지합니다. PC 복귀 시 예약 도구가 새 서버 파일을 자동 검증합니다.
- 국내 키: `powershell -NoProfile -STA -File scripts/Import-Book-Key.ps1`. 키를 채팅·인자·공개 저장소에 넣지 않습니다. 운영 활성화에는 Vercel Production 비공개 환경 변수 등록과 재배포가 필요합니다.
- 로컬 합성 성능: `npx tsx scripts/benchmark-records.ts --local-synthetic`. 운영 성능과 구분합니다. CI `ci-record-scale.ts`는 localhost 격리 PostgreSQL에서만 실행하고 합성 30,000건을 트랜잭션 종료 시 되돌립니다.

새 클라우드 생성·운영 도메인 전환·대리 수락·API 키 발급·요금제 변경은 수행하지 않습니다.
