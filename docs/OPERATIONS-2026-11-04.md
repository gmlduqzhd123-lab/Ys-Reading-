# 운영 확대·복구 개선 · 2026-11-04

> 이어지는 검색·백업 알림·Google 동시 요청·개인정보 복구·사용 흐름·광장 신고 개선은 [학급 운영 흐름 완성](OPERATIONS-COMPLETION.md)을 따릅니다.

이전 날짜의 운영 문서는 당시 이력을 보존합니다. 이번 변경은 다음 8개 범위입니다. 최종 배포 커밋·필수 검사·공개 주소는 GitHub Actions와 릴리스 채팅의 결과를 함께 확인합니다.

1. **예약 백업 안정화**: Codex 실행 파일을 현재 설치에서 찾고, Windows 예약 작업을 숨긴 실행기로 시작합니다. 기본 보관 위치는 사용자 문서 폴더의 `Bookforest-OperatorBackups/<project-ref>`입니다. Codex의 AppData 가상화와 예약 작업이 서로 다른 키·상태를 읽던 문제를 막습니다. 기존 백업은 보존합니다. PC 전원·사용자 로그인·유효한 Codex Supabase 인증이 필요합니다.
2. **감시 결과 최신성**: `/api/monitor`는 캐시하지 않습니다. 화면을 다시 보거나 온라인으로 돌아오면 갱신하고, 실제 검사 시각에서 12분을 넘긴 결과를 오래된 것으로 표시합니다.
3. **GitHub 장애·복구 알림**: 공개 연결과 감시 신호를 확인하고 저장소의 사건 이슈로 알립니다. 같은 장애를 중복 생성하지 않고 회복 시 닫습니다. 오류 원문·학생 글 대신 불투명한 오류 식별자를 사용합니다. GitHub의 알림 수신 설정과 예약 지연은 별도입니다.
4. **이동식 암호화 복구 보관**: 한글 경로를 지원하는 `Recovery-Kit-Window.ps1`에서 운영자가 직접 암호를 입력합니다. `backup.bfbak`, `recovery.bfkey`, `receipt.json`을 한 폴더로 만듭니다. 성공 후 입력란을 비우며 다시 누를 필요가 없습니다. 폴더 전체를 외부 장치에 복사하고 암호는 따로 보관합니다. 자세한 절차는 [장애 복구](disaster-recovery.md)를 따릅니다.
5. **공개 배포 검사**: Vercel Production에 GitHub의 `check`, `isolated-classroom` 검사를 요구합니다. 추가형 DB 변경과 프로토콜 2 계정 작업자를 먼저 적용하고, 검사 성공 후 동일 커밋의 도메인 연결을 확인합니다. [배포와 롤백](release-safety.md)을 따릅니다.
6. **보고서 검토·대량 초안**: `/reports`에서 초안 → 검토 → 학생 공개 → 공개 철회를 구분합니다. 원본 자료가 달라지면 다시 확인하며, 기존 보고서 본문은 바꾸지 않습니다. 최대 30명의 비공개 초안을 만들고 학생별 결과를 표시합니다. 개별 작성과 일괄 작성은 학생 잠금을 같은 순서로 얻어 중복·교착을 방지합니다.
7. **공동교사·학교·대체 운영자**: `/collaboration`에서 읽기·검토·학생 관리 권한을 학급별로 구분합니다. 학생 관리만 받은 교사는 학생 글을 읽을 수 없습니다. 학교 관리 범위, 만료·회수, 양측 확인 담임 인계와 최근 2단계 인증이 필요한 대체 운영자 초대를 적용합니다. 다른 학급이나 전체 운영자 권한을 자동 부여하지 않습니다.
8. **수업 기기·동시 사용 확인**: `/device-check`는 보안 연결·저장소·암호화·실제 서버 응답·팝업을 점검하고, 직접 확인한 수업 항목을 결과 파일로 보관합니다. CI는 합성 학생 30명의 로그인·독서·제출·출석·재시도를 실제 격리 Auth/DB로 검사합니다. CI 속도는 학교 기기나 운영 서버의 성능 보장이 아닙니다.

## 검증 범위

- 로컬 TypeScript, 45개 파일의 자동 검사 387개, 프로덕션 빌드를 통과했습니다.
- 격리 CI의 브라우저 7개 검사와 학생 30명의 동시 흐름, 공동교사 검토·중복 보상 차단·학생 계정 발급·암호 재발급·회수 후 거부를 확인했습니다. 보고서 동시 생성은 학생별 비공개 1판만 저장되는지 검사합니다.
- CI의 이동식 암호화 파일 검증과 별도 PostgreSQL/Auth/Data API 복원은 합성 자료만 사용합니다. 복원한 비밀번호·MFA 로그인, 학생별 독서·공개 보고서 접근, 익명 접근 거부를 검사합니다. 기존 운영 백업이나 실제 사용자의 인증 비밀값을 GitHub에 보내지 않습니다.
- Windows 예약 작업의 실제 종료 코드 0과 101개 테이블·155개 외래키·85개 정책의 백업 복원 검증을 확인했습니다. 실제 운영자는 유지하고 실사용 학생 자료를 시험에 사용하지 않았습니다.
- 복구 폴더를 이 PC에 생성한 사실은 외부 장치 복사·다른 PC 검증과 다릅니다. 실제 학교 기기·학교망, 별도 학교 Google 계정, 새 클라우드 프로젝트로의 Auth/OAuth 전환은 현장 확인이 필요합니다. 유료 요금제나 PITR은 활성화하지 않았습니다.
